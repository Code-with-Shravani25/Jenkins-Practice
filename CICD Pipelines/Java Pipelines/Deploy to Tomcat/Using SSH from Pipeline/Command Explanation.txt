Explanation of SCP and SSH Commands Used in Jenkins Pipeline

1. Copy the WAR file to the Tomcat server

Command:

    scp -o StrictHostKeyChecking=no target/*.war ${REMOTE_USER}@${REMOTE_HOST}:${REMOTE_PATH}

What is scp?

scp (Secure Copy Protocol) securely copies files between machines over
SSH.

Breakdown

-   scp – Starts the secure copy command.
-   -o StrictHostKeyChecking=no – Automatically accepts the remote
    server’s SSH host key so Jenkins doesn’t stop waiting for
    confirmation.
-   target/*.war – The WAR file generated by mvn package.
-   ${REMOTE_USER} – Remote login user (e.g. ubuntu).
-   ${REMOTE_HOST} – Remote Tomcat server IP address.
-   ${REMOTE_PATH} – Destination directory (/opt/tomcat/webapps).

Example after variable substitution:

    scp -o StrictHostKeyChecking=no target/jenkins-demo-app.war ubuntu@172.31.90.43:/opt/tomcat/webapps

This copies the WAR file from the Jenkins server to the Tomcat server.

------------------------------------------------------------------------

2. Connect to the remote server

Command:

    ssh -o StrictHostKeyChecking=no ${REMOTE_USER}@${REMOTE_HOST} \

What is ssh?

SSH (Secure Shell) securely connects to another machine and runs
commands remotely.

Example:

    ssh -o StrictHostKeyChecking=no ubuntu@172.31.90.43

The trailing \ indicates the command continues on the next line.

------------------------------------------------------------------------

3. Execute commands on the remote server

Command:

    "cd /opt/tomcat/bin && ./shutdown.sh || true && sleep 5 && ./startup.sh"

Everything inside the quotes runs on the remote Tomcat server.

cd /opt/tomcat/bin

Changes to the Tomcat bin directory.

&&

Runs the next command only if the previous one succeeds.

./shutdown.sh

Stops Apache Tomcat.

|| true

If shutdown.sh fails (for example, Tomcat is already stopped), true
returns success so the Jenkins pipeline continues instead of failing.

sleep 5

Waits 5 seconds to allow Tomcat to shut down completely.

./startup.sh

Starts Apache Tomcat again.

Tomcat detects the new WAR file in the webapps directory and deploys the
application.

------------------------------------------------------------------------

Overall Flow

Jenkins Pipeline ↓ Build WAR using Maven ↓ SCP copies the WAR to
/opt/tomcat/webapps ↓ SSH connects to the remote EC2 instance ↓ Navigate
to /opt/tomcat/bin ↓ Stop Tomcat ↓ Wait 5 seconds ↓ Start Tomcat ↓
Application is deployed successfully.
